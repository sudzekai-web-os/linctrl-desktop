
## Серверы и профиль

При запуске выбери сервер или продолжи без него. Сервер добавляется по домену или IP с необязательным портом. Для демонстрационного входа используются логин `admin` и пароль `admin`. Внизу боковой панели указаны адрес, порт и имя пользователя. Меню адреса позволяет отключиться и продолжить локально или сменить сервер с повторным входом. Имя открывает профиль.

Вход выполняется через `POST /auth/login` на выбранном сервере. В Windows приложение сохраняет JWT и выбранный сервер в зашифрованном блоке `authentication` файла `appdata.json` с помощью DPAPI. Пароль не сохраняется. При запуске восстанавливается действующая сессия. Смена сервера, выход из сессии, истечение срока JWT и ответ 401 очищают её. На других платформах токен хранится только в памяти. Для сервера с TLS включите HTTPS при добавлении.

## Плагины

Помести папку с расширением `.linctrl` в каталог из страницы **Плагины**. Также проверяются `plugins/` в рабочей папке и рядом с исполняемым файлом. Нажми **Обновить список**, затем включи нужный плагин. На главной и в разделе **ПЛАГИНЫ** появится кнопка его страницы. В проекте есть тестовый плагин «Кубик» в `plugins/dice.linctrl`. Его можно включить в списке и проверить сохранение результата броска.

Минимальный `manifest.json`:

```json
{
    "id": "example.status",
    "name": "Состояние подключения",
    "summary": "Описание расширения",
    "apiVersion": 1,
    "entry": "Page.qml"
}
```

`entry` — относительный путь к QML-компоненту с корнем `Item` или производным от него типом. Плагин получает одну страницу, которой управляет сам. У `id` должны быть уникальные строчные латинские буквы, цифры или символы `.`, `_`, `-`.

Плагин может импортировать `linctrl` и читать `Session.address`, `Session.port`, `Session.endpoint`, `Session.name` и `Session.role`. `Plugins.appDataDirectory` показывает корень данных приложения. Методы `Plugins.readText(id, path)` и `Plugins.writeText(id, path, text)` работают с файлами в `plugin-data/<id>/` относительно этого каталога.

Нативную логику можно поставлять как QML-модуль Qt. Положи `qmldir` и DLL модуля с зависимостями в `imports/<URI по папкам>/` внутри пакета и импортируй его из `Page.qml`. Например, для `import Example.Status 1.0` используй `imports/Example/Status/`. В необязательном массиве `libraries` перечисли относительные пути к DLL-зависимостям в порядке загрузки. Например, укажи DLL основной библиотеки, к которой привязан сгенерированный Qt DLL-плагин. Сам DLL-плагин Qt загрузит по `qmldir`. Собирай DLL под совместимые версию Qt, архитектуру и компилятор. [Документация Qt о qmldir](https://doc.qt.io/qt-6/qtqml-modules-qmldir.html).

Включай пакеты из доверенных источников. Нативный код работает с правами процесса LinCtrl. При выключении кнопка и страница удаляются, а уже загруженные Qt библиотеки остаются в процессе до его завершения.

Плагины вызывают `Session.request(method, path, body)` для запросов к выбранному серверу и получают результат через `Session.requestFinished(id, status, data, error)`. Приложение добавляет токен к запросу. Для работы с пользователями, ролями и историей используется `database.linctrl`.

`ApiClient.request(method, path, body)` возвращает ID запроса. Сигнал `ApiClient.requestFinished(id, status, response, error)` передаёт исходные байты в `response.body` и тип содержимого в `response.contentType`. JSON также доступен в `response.json`, текст UTF-8 — в `response.text`. Обёртку можно разобрать явно через `ResponseEnvelope.read(status, response, error)`, доступный через `import linctrl`.

Каталог серверов, вход, состояние учётной записи, переходы между экранами и API-клиент вынесены в отдельные QML-модули. C++ отвечает за сетевой транспорт, локальные данные и интеграцию с Windows. Поиск, загрузка и хранение данных плагинов реализованы отдельно.
